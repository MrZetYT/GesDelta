# 08. Ответы на вопросы

QA работает только на чтение. Запускается из чата, не из Run, и может идти параллельно с Run: описание коммитится в конце запуска, версии неизменяемы, читатель всегда видит согласованное состояние.

## 1. Типы вопросов

| Тип | Примеры | Данные | Кто формирует ответ |
|---|---|---|---|
| `WhatChanged` | «Что нового за месяц?», «Что поменялось с прошлого раза?», «Какие продвижения по нейросимвольным системам?» | `changes` (Done), `runs` | код, шаблон |
| `WhenFirst` | «Когда впервые появилось понятие Y?» | `snapshots`, `materials`, полнотекстовый поиск | код, шаблон |
| `Explain` | «Что такое Z?» | текущая версия Description, `claims`, `claim_evidence` | LLM, по найденному |
| `Unknown` | всё остальное | нет | фиксированная фраза |

- «Продвижения» это `WhatChanged` с `terms`. Оценку важности («прорыв») система не делает: Analyzer пишет summary, а не рейтинг.
- Вопросы про общие знания и вне накопленных данных → `Unknown`. QA не отвечает «из головы модели».

## 2. Как агент находит данные

Три шага (03). LLM не пишет SQL и не вызывает инструменты.

**Шаг 1 (LLM): разбор вопроса.** Вход `{ question, today }`. Выход:

```json
{ "type": "WhatChanged | WhenFirst | Explain | Unknown",
  "params": { "period": null, "terms": [] } }
```

- `period`: `null` или `"sinceLastRun"` (то же самое), или `{ "from": "2026-09-01", "to": "2026-10-09" }`. Относительные периоды («за месяц») LLM переводит в даты по `today`.
- `terms`: до 5 вариантов понятия или темы: русские формы и английский перевод (источники в основном английские, словарь `simple` морфологии не знает). Для `WhenFirst` и `Explain` нужен минимум один term, иначе `Unknown`.
- Код валидирует JSON, даты (`from ≤ to ≤ today`), число и длину terms (до 5, до 60 символов). Невалидно: один повтор с замечанием, затем «не смог разобрать вопрос» (фраза `Unknown`).
- **Время:** `today` в шаге 1 это локальная дата компьютера. `from` и `to` вопроса тоже локальные: код переводит их в UTC (`from` = локальная полночь `from`, `@toExclusive` = локальная полночь на следующий день после `to`). Даты в ответах показываются в локальном времени.

**Шаг 2 (код): запрос по `type`.**

| Тип | Запрос (04, раздел 4) |
|---|---|
| WhatChanged | Done-изменения за период или с последнего коммита описания; при непустых `terms` фильтр по summary, заголовку и тексту новой версии |
| WhenFirst | Первый снимок с совпадением по `terms` |
| Explain | Разделы текущей версии Description с совпадением по `terms` (в памяти, регистр не важен) + до 5 Claims с совпадением по `claims.text` и их Evidence |

Поиск по `terms`: код собирает строку вида `"a" or "b" or "c"` и передаёт в `websearch_to_tsquery('simple', ...)`. Он не падает на спецсимволах. Для ILIKE код экранирует `%` и `_`.

**Шаг 3 (LLM): только для `Explain`.** См. раздел 3.

## 3. Формат ответа

Язык русский, даты `дд.мм.гггг`. Дата Change это `done_at` (когда изменение попало в описание).

### WhatChanged (шаблон, LLM не вызывается)

```
Изменений: N. {период или «С последнего обновления описания (дд.мм.гггг)»}[, по запросу: terms]

1. дд.мм.гггг · Новое / Обновлено · {summary}
   {заголовок материала} — {url}
...
[и ещё M, сузь период или тему]
[Последняя проверка дд.мм.гггг: изменений нет.]
```

- Показываем до 10 записей, новые первыми.
- `sinceLastRun` = Change из последней фиксации описания (максимальный `done_at`).
- Последняя строка выводится, если самый свежий Run это `NoChanges` и он позже последней фиксации.
- Список ссылок для проверки собирает код из строк БД: «ссылка и дата» и «не выдумывает» выполняются по построению.

### WhenFirst (шаблон, LLM не вызывается)

```
В наших данных впервые встретилось {дата получения}: {заголовок}.
Опубликовано: {дата публикации или «дата неизвестна»}. {url}
Это «в наших данных», не обязательно первое появление в мире.
```

### Explain (LLM, шаг 3)

Вход: вопрос, найденные разделы (с маркерами `[c:id]`), найденные Claims. Лимит `ContextMaxChars` (разделы обрезаются по порядку совпадения). Выход:

```json
{ "ok": true, "answer": "Текст с маркерами [c:42].", "noData": false }
```

- 3-6 предложений, только по переданному, каждое утверждение с маркером `[c:id]`.
- Код проверяет: каждый маркер входит в переданный набор, `answer` непустой (или `noData = true`). Нарушение: один повтор с замечанием. После него вместо ответа код выводит шаблонный список найденных Claims.
- Код заменяет маркеры на сноски `[1]` и добавляет список: `[1] {заголовок}, {дата публикации или «получено дд.мм.гггг»}, {url} · один источник / подтверждено N источниками`. N = число разных Material среди Evidence Claim (считает код по БД). Цитата `quote_ru` доступна в UI по клику.

## 4. Нет данных

Пустой результат шага 2: фиксированная фраза, LLM не вызывается. Фразы лежат в ресурсах.

| Ситуация                                                       | Фраза                                                                                                                                                                                                                                           |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WhatChanged, пусто, `period` задан датами                      | «За этот период изменений в данных нет.»                                                                                                                                                                                                        |
| WhatChanged, пусто, `period` = null / `sinceLastRun` (с terms) | «С последнего обновления описания по «{term}» изменений нет.»                                                                                                                                                                                   |
| WhatChanged, описание ещё не обновлялось                       | «Описание ещё не обновлялось, изменений в данных нет.»                                                                                                                                                                                          |
| WhenFirst пуст                                                 | «Понятие «{term}» в наших данных не встречается.»                                                                                                                                                                                               |
| Explain пуст, или `noData = true`                              | «В накопленных данных про «{term}» ничего нет.»                                                                                                                                                                                                 |
| Unknown                                                        | «Не понял вопрос. Я отвечаю на вопросы трёх видов: что изменилось (за период или с прошлого обновления), когда понятие впервые встретилось, что такое понятие по накопленным данным. Предыдущие вопросы я не помню, формулируй вопрос целиком.» |
| Вся цепочка LLM недоступна                                     | «Модель сейчас недоступна, попробуй позже. Кнопка «Что изменилось с прошлого запуска» работает без модели.»                                                                                                                                     |

## 5. Контекст диалога

В MVP без памяти: каждый вопрос независим. История показывается в UI, но модели не передаётся.

**Пользователя предупреждаем:** в чате под полем ввода постоянная подсказка: «Каждый вопрос обрабатывается отдельно, прошлые не учитываются. Формулируй целиком: тема, период, понятие.» Фраза `Unknown` повторяет это.

Диплом: передача последних двух пар в шаг 1 для «а когда это было?».

## 6. Модель и недоступность

Тот же `FallbackLlmClient` и цепочка из конфига (07). Отдельной модели под QA нет.

- Профиль QA, чтобы чат не висел: 1 повтор, пауза 5 с, таймаут вызова 60 с.
- Свап действует в пределах одного вопроса (шаги 1 и 3), между вопросами не хранится: каждый вопрос начинает с основной модели. Уведомление о свапе идёт в журнал, как в 07.
- Вся цепочка лежит: фраза из раздела 4. Это не «в данных нет», чтобы не путать.
- Кнопка-шорткат «Что изменилось с прошлого запуска» вызывает шаги 2 и шаблон без LLM, работает даже при недоступной цепочке (`IMonitoringService.GetChangesSinceLastRun()`).

```json
"Qa": {
  "MaxTerms": 5, "MaxListItems": 10, "ContextMaxChars": 12000,
  "Llm": { "NetworkRetries": 1, "NetworkPausesSec": [5],
           "RateLimitRetries": 1, "RateLimitPausesSec": [5], "CallTimeoutSec": 60 }
}
```

## 7. Примеры вопрос → ответ

> Данные примерные, для показа формата.

**Вопрос:** «Что с последнего раза поменялось в гибридных интеллектуальных системах?»
Шаг 1: `WhatChanged`, `period = sinceLastRun`, `terms = []`.
**Ответ:**
```
Изменений: 2. С последнего обновления описания (08.10.2026)

1. 08.10.2026 · Новое · Описан нейросимвольный подход с логическим выводом поверх обученных представлений.
   <заголовок статьи> — <ссылка>
2. 08.10.2026 · Обновлено · В статью добавлен раздел о применении в робототехнике.
   <заголовок статьи> — <ссылка>
```

**Вопрос:** «Когда впервые появилось понятие «нейросимвольный»?»
Шаг 1: `WhenFirst`, `terms = ["нейросимвольный", "нейросимвольные", "neurosymbolic", "neuro-symbolic"]`.
**Ответ:** по шаблону WhenFirst.

**Вопрос:** «Что такое нейросимвольная система?»
Шаг 1: `Explain`. **Ответ:** 3-6 предложений со сносками `[1]`, `[2]` и списком источников.

**Вопрос:** «Что изменилось по квантовым вычислениям?» (в данных нет)
**Ответ:** «За этот период изменений в данных нет.» (LLM в шаге 3 не вызывался.)

**Вопрос:** «А когда это было?» (без контекста)
**Ответ:** фраза `Unknown`.
