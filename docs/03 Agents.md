# 03. Паспорта агентов

> Не больше 10 инструментов на агента.

## Общие правила

- LLM-агенты возвращают структурированный JSON. Код-шаги возвращают типизированные результаты (C# records), контракты описаны в коде.
- Отказ: `{ "ok": false, "reason": "...", "retryHint": "..." }`
- Лимит попыток: Analyzer 3 (всего, включая первую). Остальное в 07_ORCHESTRATION.
- LLM не выдумывает id из БД. Новые сущности адресуются локальными ссылками (`c1`, `c2`), реальные id присваивает код.
- `Claim.text` пишется на языке описания (язык описания русский, 09), `quote` дословно на языке источника.
- Агент собирает работу из тулов (интерфейсы в Core, реализации в Tools), см. 02, раздел 6.

## Карта шагов MVP

| Шаг               | Тип                 | Что делает                                                            |
| ----------------- | ------------------- | --------------------------------------------------------------------- |
| Collector         | код                 | Берёт записи из источника                                             |
| Parser            | код                 | Очищает и нормализует текст                                           |
| Detector          | код                 | Сравнивает со снимком, решает значимость, сохраняет Snapshot и Change |
| Analyzer          | LLM                 | По одному Change возвращает правки описания и Claims                  |
| Critic            | код (LLM на диплом) | Проверяет ответ Analyzer                                              |
| DescriptionWriter | код                 | Применяет правки, пишет версию, коммитит Run                          |
| Reporter          | LLM, диплом         | Полный отчёт по Run (заглушка)                                        |
| QA                | гибрид              | Отвечает на вопросы пользователя                                      |

Detector добавлен отдельным шагом: Parser не знает про БД, а сравнение требует прошлого снимка.

## Агент: Collector (сборщик)

**Роль:** Получить сырые записи из источника.
**Тип:** код **Модель:** нет

**Вход:**

```json
{ "sourceId": 1, "type": "Rss", "url": "", "config": {}, "maxItems": 10 }
```

`maxItems` = `config.maxItems` или `Sources.MaxItemsPerSource` (05, раздел 3).

**Выход:**

```json
{
  "ok": true,
  "sourceId": 1,
  "items": [
    { "externalId": "", "title": "", "url": "", "publishedAt": null, "rawText": "", "fromPage": false }
  ]
}
```

`fromPage = true`: `rawText` это HTML страницы (тип Html всегда, Rss при докачке по `fullText`). `false`: текст ленты (RSS HTML-фрагмент, arXiv title + abstract).

`externalId`: guid (RSS), id (arXiv, без суффикса версии), канонический URL (остальные), D-012. Для HTML `rawText` это HTML страницы.

**Инструменты:** ISourceFetcher (реализации Rss / Arxiv / Html), IRobotsPolicy.
**Критерий «принято»:** ответ получен. Пустая выдача не ошибка (поведение при пустом ответе: 05).
**При отказе:** `reason` = `timeout | http_5xx | http_429 | format_changed | http_404 | http_403 | robots_disallowed`. Временные сбои: повтор внутри Collector с паузой. Постоянные: источник помечается `failed`, запуск продолжается.
**Лимит итераций:** 3 повтора, паузы 2/5/10 с (07).
**Открыто:** Решено в 05, раздел 4.1 (fullText = auto).

## Агент: Parser (парсер)

**Роль:** Превратить сырую запись в нормализованный текст.
**Тип:** код **Модель:** нет

**Вход:** `{ "item": { /* из Collector */ }, "sourceType": "Rss", "config": {} }`

Для `fromPage = true` вызывает `IContentExtractor`, иначе только чистит HTML ленты. В сеть не ходит.

**Выход:**

```json
{ "ok": true, "externalId": "", "title": "", "url": "", "publishedAt": null, "cleanText": "", "contentHash": "" }
```

**Инструменты:** IContentExtractor (SmartReader/AngleSharp), нормализация по 06, SHA256.
**Критерий «принято»:** `cleanText` не пустой.
**При отказе:** `{ "ok": false, "reason": "parse_error" }`, материал пропускается и считается в `stats.failed`. Возврат в Collector не делается (D-025). Проверку «короче 20% прошлого снимка» делает Detector: ему нужна БД.

## Агент: Detector (детектор изменений)

**Роль:** Решить, значимо ли изменение, и атомарно сохранить результат.
**Тип:** код **Модель:** нет

**Вход:** результат Parser + `sourceId`. Прошлый снимок Detector читает из БД через Storage. Материалы приходят уже упорядоченной очередью (round-robin по источникам, свежие вперёд), порядок формирует Оркестратор после Parser (05, раздел 5). Detector только считает бюджет. Для существующего Material Detector читает из БД два снимка: последний (проверка хэша и ошибки разбора) и базовый, то есть `new_snapshot_id` самого свежего Change материала (основа для diff, 06, раздел 3).

**Выход:**

```json
{
  "verdict": "New | Updated | Noise | Unchanged | ParseError | OverBudget",
  "changeId": null,
  "addedFragments": []
}
```

**Правила:** 06_CHANGE_DETECTION (хэш → diff по абзацам → пороги). `ISignificanceJudge` за интерфейсом.
**Инструменты:** ITextDiffer (DiffPlex), ISignificanceJudge.
**Запись:** New: Material + Snapshot + Change (Pending) одной транзакцией. Updated: Snapshot + Change (Pending) одной транзакцией. Noise: только Snapshot. Unchanged: только `last_seen_at`. ParseError и OverBudget: ничего не пишется. `last_seen_at` обновляется при любом вердикте, кроме ParseError и OverBudget.
**Бюджет новых Material:** MaxNewMaterialsPerRun из RunContext (05, раздел 5).
**LLM не вызывается никогда.**

## Агент: Analyzer (анализатор)

**Роль:** По одному Change вернуть правки описания и подтверждённые цитатами утверждения.
**Тип:** LLM **Модель:** сильная из доступных (см. 10_LLM_CONFIG)

**Вход:**

```json
{
  "changeId": 123,
  "topic": "гибридные интеллектуальные системы",
  "kind": "New",
  "material": { "title": "", "url": "", "publishedAt": null },
  "text": "",
  "textIsFragment": false,
  "description": {
    "sections": [ { "sectionId": "", "title": "", "text": "" } ]
  },
  "existingClaims": [ { "claimId": 42, "sectionId": "", "text": "" } ],
  "feedback": null
}
```

- `kind = New`: `text` это `clean_text` материала, обрезанный с конца до `Analyzer.MaxTextChars` (10, раздел 7); при обрезке в промпт добавляется пометка. Для `Updated` тот же лимит на добавленные фрагменты., `textIsFragment = false`.
- `kind = Updated`: `text` это только добавленные фрагменты, `textIsFragment = true` (06, D-020).
- `description` пуст при самом первом Change. Описание содержит уже применённые правки предыдущих Change этого Run.
- `feedback` при повторе: `{ "attempt": 2, "reason": "", "retryHint": "" }`.
- existingClaims = Claims из БД + Claims из RunContext (принятые ранее в этом Run)
- `existingClaims` передаются целиком, лимита в MVP нет (10, раздел 7)

**Выход:**

```json
{
  "ok": true,
  "relevant": true,
  "summary": "",
  "claims": [ { "ref": "c1", "text": "", "quote": "", "quoteRu": "" } ],
  "confirms": [ { "claimId": 42, "quote": "", "quoteRu": "" } ],
  "operations": [
    { "op": "add_section", "title": "", "content": "Текст с маркерами [[c1]]" },
    { "op": "append_to_section", "sectionId": "", "content": "Текст с маркерами [[c2]]" }
  ]
}
```

- `summary`: 1-3 предложения для журнала.
- `claims`: новые утверждения. `quote` дословно из `text`.
- `confirms`: материал подтверждает уже существующий Claim, `quote` из `text`. Код добавляет ClaimEvidence. Так «N источников» работает в MVP без эмбеддингов.
- `relevant = false`: материал не по теме, `claims`, `confirms`, `operations` пусты.
- `relevant = true`, `operations` пусты, `confirms` непуст: допустимо (Critic №9). Change получит `Skipped`, Evidence запишутся, описание не меняется (D-053).
- `sectionId` берётся только из `description.sections`.

**Инструменты:** нет в MVP: весь контекст в запросе (проще и надёжнее для слабых моделей). На диплом возможны тулы через AIFunctionFactory (02, раздел 6).

**Правила промпта (ограничения):**
- Использовать только переданный текст, ничего не добавлять от себя.
- Цитата дословная, без правки.
- Каждый факт в `content` помечен маркером своего Claim.
- Не переписывать и не повторять уже имеющееся в описании.
- Не выдумывать `sectionId` и `claimId`.
- `quote` дословно из текста (оригинал), `quoteRu` перевод этой цитаты на русский.
- Писать по-русски, термин с оригиналом в скобках. В content только маркеры \[[cN]], готовых [c:N] не писать. Каждый абзац с маркером. Строк, начинающихся с #, не использовать. Не длиннее лимитов (09).

**Критерий «результат принят»:** Critic вернул `ok: true`.
**При отказе:** Critic возвращает `{ ok: false, reason, retryHint }` → Analyzer повторяет с `feedback`.
**Лимит итераций:** 3 попытки. После: Change = Failed, правки не применяются, запись в лог и `stats.analysisFailed`. Недоступность LLM (сеть, 429, таймаут) не считается попыткой: повтор с паузой, затем свап модели (07, раздел 2.1). Каждая попытка (включая повторы после Critic) увеличивает `stats.analyzerCalls` и пишется в трассу (11, раздел 2)
**Промпт:** `/prompts/analyzer.md` (EmbeddedResource, версия в первой строке, 10, раздел 5)

## Агент: Critic (критик)

**Роль:** Отбраковать ответ Analyzer до применения.
**Тип:** код в MVP (LLM-критик на диплом, D-025) **Модель:** нет

**Вход:** ответ Analyzer + входные данные вызова (`text`, `description`, `existingClaims`).
**Выход:** `{ "ok": true }` или `{ "ok": false, "reason": "...", "retryHint": "..." }`.

`reason` содержит все найденные нарушения списком, чтобы одна попытка исправила всё.

| #   | Проверка                                                                                                                                                                                                   | Пример замечания                                          |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 1   | JSON парсится и соответствует схеме                                                                                                                                                                        | «JSON невалиден: нет поля operations»                     |
| 2   | `ok: true` → `summary` не пустой и не длиннее лимита                                                                                                                                                       | «summary пустой»                                          |
| 3   | `relevant: false` → claims/confirms/operations пусты                                                                                                                                                       | «relevant=false, но есть операции»                        |
| 4   | `quote` каждого Claim найден в `text` (пробелы нормализуются, иначе точное совпадение) (проверяется только `quote`, не `quoteRu`) Проверяется по тому же `text`, что был передан Analyzer (после обрезки). | «цитата c3 не найдена в тексте»                           |
| 5   | Длина `quote` в пределах [мин, макс] из конфига. (только `quote`, не `quoteRu`)                                                                                                                            | «цитата c2 слишком короткая»                              |
| 6   | `ref` уникальны. Каждый маркер `[[cN]]` в операциях ссылается на объявленный Claim. Каждый объявленный Claim использован хотя бы раз                                                                       | «маркер \[[c4]] не объявлен»                              |
| 7   | `append_to_section.sectionId` существует.                                                                                                                                                                  | «раздел s9 не существует»                                 |
| 8   | `confirms.claimId` есть в `existingClaims`, цитата найдена в `text`                                                                                                                                        | «claimId 77 не передавался»                               |
| 9   | `relevant: true` → есть хотя бы одна операция или confirm                                                                                                                                                  | «нечего применять»                                        |
| 10  | `quoteRu` у каждого Claim и confirm не пустой\|                                                                                                                                                            | «у цитаты c2 нет перевода»                                |
| 11  | Каждый абзац `content` (блок между пустыми строками) содержит хотя бы один маркер `[[cN]]`                                                                                                                 | «абзац 2 без маркера»                                     |
| 12  | В `content` нет готовых маркеров `[c:N]` и нет строк, начинающихся с `#`; длина не больше `ContentMaxChars`                                                                                                | «в content есть [c:7], пиши только \[[cN]]»               |
| 13  | Дубликат заголовка по slug (правила и дополнительные условия в 09, раздел 2). Учитываются и разделы, добавленные ранее в этом же ответе                                                                    | «заголовок «Нейросети!» совпадает с разделом «нейросети»» |

Пороги в конфиге. Смысловую проверку (следует ли вывод из текста) код не делает: известное ограничение MVP.

## Шаг: DescriptionWriter (код)

**Роль:** Собрать новую версию Description и закоммитить Run.
**Тип:** код

- Алгоритм в 09, раздел 3: резервирование id Claim (sequence), замена маркеров, применение операций в памяти, Claims и Evidence копятся в RunContext. В конце Run файл (если были операции) и одна транзакция: Claims, Evidence, `document_versions` (если есть версия), `changes`: Done с `summary` и `done_at` для Change с операциями, Skipped для Change только с `confirms`.
- Тест-инвариант: каждая предыдущая версия содержится в новой (11).

## Агент: Reporter (составитель отчёта) — диплом

Заглушка. Формирует полный отчёт по Run (структура: Что было → Что нового → Что изменилось → Источники, см. 09), сохраняет как Document `kind = Report`, неизменяемый файл. В MVP не реализуется (D-026).

## Агент: QA (отвечает на вопросы)

**Роль:** Ответить на вопрос по накопленным данным со ссылками на источники и даты.
**Тип:** гибрид: LLM разбирает вопрос и формулирует ответ, код выполняет запросы.
**Модель:** цепочка из 07, профиль повторов QA в 08, раздел 6

**Шаг 1 (LLM), разбор вопроса.**

Вход: `{ "question": "", "today": "2026-10-09" }`.

Выход:

```json
{ "type": "WhatChanged | WhenFirst | Explain | Unknown", "params": { "period": null, "terms": [] } }
```

Правила period и terms из 08, раздел 2

**Шаг 2 (код).** Фиксированные параметризованные запросы из 04 (раздел 4) по `type`. LLM не пишет SQL и не вызывает инструменты.

**Шаг 3 (LLM), ответ только по результатам шага 2.**

Только для Explain
Выход:

```json
{ "ok": true, "answer": "текст с маркерами [c:id]", "noData": false }
```

WhatChanged и WhenFirst отвечает код по шаблону (08).

**Правила:**
- Пустой результат шага 2 → `noData = true`, ответ фиксированной фразой «в данных нет», LLM не вызывается.
- Каждый маркер [c:id] в ответе проверяется кодом: он должен быть в переданном наборе Claims. Нарушение: 1 повтор, затем шаблонный список Claims.
- «Когда впервые появилось» отвечаем с оговоркой «в наших данных» и датой публикации, если она есть (04).

**Инструменты LLM:** Инструменты LLM: нет в MVP.
**Контекст диалога, форматы ответов, примеры:** 08_QA.
**Трасса:** `logs/llm/qa/{qaId}.json` (11, раздел 2).

## Известные риски

- Бесплатные модели могут не тянуть строгий JSON с операциями. Проверяем на golden set (11_QUALITY), запасной путь: вариант A из D-027.
- Дубли фактов в разных разделах: Analyzer видит всё описание, но модель может пропустить. Ловим поиском по Claims, позже эмбеддингами.
- Описание растёт. Пока оно целиком влезает в контекст (порог в конфиге), передаём его целиком. Что делать после порога: решаем по результатам первых прогонов.
- Порог и поведение при превышении: 10, раздел 7.
- Prompt injection из текста материала Critic не ловит: инструкцию можно процитировать как обычную цитату. Смягчение: данные в тегах (D-042), ограниченные операции, golden set кейс 8. `quoteRu` проверяется только на непустоту.
