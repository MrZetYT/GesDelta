# 05. Источники данных

Источники задаёт пользователь (в MVP автопоиска нет). Реестр описывает **типы** источников, которые умеет система.

## 1. Реестр типов источников

| Тип | Доступ | Ключ | Что такое Material | external_id | Статус |
|---|---|---|---|---|---|
| `Rss` | RSS / Atom лента | нет | запись ленты | `guid` записи (нет guid: канонический URL) | MVP |
| `Arxiv` | Atom API `export.arxiv.org` | нет | работа (title + abstract) | id без версии, например `2401.12345` или `hep-th/9901001` | MVP |
| `Html` | одна страница | нет | страница целиком | канонический URL (D-012) | MVP |
| Поиск (Tavily / Brave) | Search API | да | найденная страница | канонический URL | диплом |

Поиск источников агентом (Tavily / Brave) вне MVP: на дипломе оформляется тулом `ISourceSearcher` для `AgenticRunPipeline` (02, D-029).

## 2. Выбор источников под тему

Тема демо: «гибридные интеллектуальные системы».

- arXiv: поисковый запрос по теме.
- Habr: RSS по теме.
- 1-2 англоязычных RSS-блога.

Критерий «минимум 5 материалов при первом запуске» выполняется при 2-3 живых источниках. Конкретные URL подбираем на реальных данных и записываем сюда.
**Источники демо (подобраны на реальных данных):**

- **Arxiv:** `url` = `https://export.arxiv.org/api/query`, `config` = `{ "query": "neurosymbolic", "maxItems": 10 }`. Свежие работы по теме.
- **Rss:** `url` = `https://habr.com/ru/rss/hubs/machine_learning/articles/?fl=ru`, `config` = `{ "fullText": "auto" }`. В ленте 40 записей, в `description` только анонс (~800 символов), поэтому при `auto` страница докачивается. Хаб широкий, часть материалов нерелевантна теме: полезно для проверки `relevant = false`.
	- `robots.txt` разрешает статьи; для `*` стоит `Crawl-delay: 10`; докачка идёт по чистому адресу без `utm`

## 3. Как пользователь задаёт источник

В окне настройки: тип из списка + поля под тип. Автоопределение типа по URL не делаем.

| Тип | Что вводит пользователь | `sources.url` | `sources.config` |
|---|---|---|---|
| Rss | URL ленты | URL ленты | `{ "fullText": "auto" }` |
| Html | URL страницы | URL страницы | `{}` |
| Arxiv | поисковый запрос | базовый адрес API | `{ "query": "hybrid intelligent systems", "maxItems": 10 }` |

## 4. Нормализация

Collector отдаёт единый вид (03): `externalId, title, url, publishedAt, rawText`. Автора не храним: в схеме его нет.

| Тип | rawText | publishedAt | Особенности |
|---|---|---|---|
| Rss | текст ленты или страницы (по `fullText`, ниже) | `pubDate` / `published` | HTML внутри очищает Parser (06) |
| Arxiv | `title` + `abstract` | `published` (дата первой версии) | PDF не качаем. Сортировка по дате подачи, новые первыми |
| Html | HTML страницы | нет (null) | Основной контент извлекает Parser (SmartReader / AngleSharp) |

`maxItems` (сколько записей брать с источника за запуск) необязателен для любого типа. Если не задан, берётся `Sources.MaxItemsPerSource`. Поле в UI не выводим. Это число скачанных записей, а не потолок новых материалов (раздел 5).

### 4.1. RSS: анонс или полный текст

Параметр `config.fullText`:
- `auto` (по умолчанию): берём текст ленты, если он длиннее `RssFullTextMinChars` (1500, в конфиге; длина считается по `rawText` ленты как есть, порог грубый). Иначе **Collector** скачивает страницу (`ISourceFetcher`, проверка `IRobotsPolicy`) и отдаёт её HTML с `fromPage = true`. Страница не открылась или запрещена robots: отдаём анонс с `fromPage = false`, пишем в лог. Докачка идёт по `guid` или `link` без `utm` и фрагмента (D-060)
- `never`: только лента.
- `always`: всегда страница.

Смена режима меняет `clean_text`, значит хэш и новые Snapshot. Поэтому после первого запуска поле в UI неизменяемо.

### 4.2. arXiv: версии

В id записи есть версия (`.../abs/2401.12345v2`). `external_id` = id без суффикса версии. Выход v2 с изменённым abstract проходит обычный путь `Updated` (06). Правка abstract часто мала и уходит в шум по порогам: это нормально.

### 4.3. Html в MVP

Одна страница = один Material. Подходит страница вроде «What's new», которая со временем получает новые абзацы (`Updated`). Страницы-списки с обходом ссылок вне MVP.

## 5. Потолок материалов

`MaxNewMaterialsPerRun = 10` на тему (в конфиге), для первого запуска и для остальных. Защита лимитов бесплатных моделей.

- Новые материалы набираются по кругу по источникам, самые свежие вперёд.
- Не вошедшие не сохраняются: Material не создаётся, в следующий запуск они снова «новые».
- `Updated` потолком не ограничиваем.
- Pending с прошлых запусков в потолок не входят.
- Очередь материалов (по кругу по источникам, свежие вперёд) формирует Оркестратор после Parser. Бюджет новых хранится в `RunContext`, считает Detector: создаёт Material только в пределах бюджета, остальным возвращает `OverBudget`.

## 6. Ошибки и деградация

Общая таблица реакций: 07, раздел 7. Уточнения по источникам:

| Ситуация | Поведение |
|---|---|
| Источник недоступен | `reason` = `timeout / http_5xx / http_429`: повторы Collector (07), затем источник `failed`, запуск продолжается |
| Страница не найдена, доступ закрыт | `http_404 / http_403`: без повторов, источник `failed` |
| Изменился формат ответа | `format_changed`: ответ не разбирается как RSS/Atom/arXiv-Atom, или Parser не нашёл основной контент HTML-страницы. Источник `failed`, лог |
| Превышен лимит | 429: паузы и повторы (07). Для arXiv также учитывать `Retry-After`, если он есть |
| Пустой ответ | Не ошибка. Если раньше у источника были материалы: `warning` в лог (подозрение на сломанный запрос или ленту) |
| Запрещено robots.txt | `robots_disallowed`: материал или источник пропускается как `failed` |

`failed` у источника сам не снимается и не хранится: он живёт в `runs.stats`, следующий запуск пробует источник снова. Колонки в `sources` не добавляем.

## 7. Как добавить новый источник

1. Реализовать `ISourceFetcher` (Core) в проекте Tools. Вернуть `externalId, title, url, publishedAt, rawText` или отказ `{ ok:false, reason }` (03).
2. Добавить значение в `sources.type` и в список типов окна настройки.
3. Зарегистрировать реализацию в DI по ключу типа.
4. Описать, что вводит пользователь и что лежит в `config` (таблица в разделе 3), правило `external_id` (раздел 1).
5. Записанный реальный ответ положить в тестовые данные, написать тест: разбор, `external_id`, пустая выдача, битый формат.
6. Если тип ходит на HTML-страницы: проверка robots и паузы работают автоматически через общие тулы (раздел 8).

## 8. Этика и правовые моменты

- **User-Agent:** свой, с названием проекта и контактом (в конфиге).
- **Паузы:** запросы к одному хосту строго последовательно. Пауза на хост: значение из `HostDelaysMs`, иначе `HostDelayMs` (1 с, D-060). Для arXiv не реже раза в 3 с и одно соединение за раз (условия API arXiv). Collector и так работает последовательно.
- **robots.txt:** проверяем при заходе на HTML-страницу (тип `Html` и полный текст для RSS) через `IRobotsPolicy`. RSS и API не проверяем, они для машин. Кэш на время запуска. 404 на robots.txt = можно. 5xx или таймаут = в этом запуске считаем запрещённым.
- **Хранение:** тексты храним локально, для личного и исследовательского использования, наружу не публикуем. Ссылка на источник в описании обязательна (через Claim).
- **ETag / If-Modified-Since:** не делаем. Нагрузка мизерная (раз в неделю), хэш защищает от лишней работы.

```json
"Sources": {
  "UserAgent": "GesDelta/1.0 (<контакт>)",
  "HostDelayMs": 1000,
  "HostDelaysMs": { "habr.com": 10000 },
  "ArxivDelayMs": 3000,
  "RssFullTextMinChars": 1500,
  "MaxNewMaterialsPerRun": 10,
  "MaxItemsPerSource": 20
}
```
