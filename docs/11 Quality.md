# 11. Качество: логи, отладка, тесты

## 1. Что логируем

Инструмент: Serilog, файлы (Serilog.Sinks.File), rolling по дням, хранение 30 дней, папка `%LOCALAPPDATA%/GesDelta/logs`. В БД логи не кладём (D-044).

Правила:
- В обычный лог идут только метаданные: идентификаторы, счётчики, длительности, размеры в символах, причины. Тексты материалов, промпты и ответы моделей в обычный лог не пишем, они только в трассах (раздел 2).
- Ключи API не пишутся никуда.

| Шаг | Что пишем в обычный лог |
|---|---|
| Любой агент | имя шага, runId, длительность, токены (для LLM), номер попытки, размеры входа и выхода |
| Collector | источник, число записей, `reason` отказа, номер повтора и пауза |
| Parser | число принятых и отклонённых (`parse_error`) |
| Detector | вердикт по каждому материалу (materialId, verdict), суммарная длина добавленных абзацев; итоговые счётчики |
| Analyzer | changeId, номер попытки, вердикт Critic, модель, `promptVersion`, токены |
| Critic | вердикт и `reason` |
| Оркестратор | переходы между шагами, итог Run (статус, stats) |
| LLM-клиент | свап модели: причина, модель до и после; повторы с причиной |
| Планировщик | решение «запустить» и почему (интервал, RetryDelay, trigger); смена причины «не запускаем»; серия «нечистых» Run. Не каждый тик |
| Старт приложения | сколько Run закрыто как `interrupted`, применённые миграции, нет ключа OpenRouter |
| QA | qaId, `type`, `period`, число terms, число строк шага 2, результат проверки маркеров, токены |

```json
"Logging": { "Dir": "%LOCALAPPDATA%/GesDelta/logs", "RetainDays": 30, "TraceLlm": true }
```

## 2. Отладка «агент вернул чушь»

Каждая LLM-попытка пишется отдельным JSON-файлом (трасса).

- Analyzer: `logs/llm/{runId}/change-{changeId}-try-{n}.json`
- QA: `logs/llm/qa/{qaId}.json`, внутри массив вызовов (шаг, попытка)

Содержимое трассы:

```json
{
  "runId": 0, "changeId": 0, "attempt": 1,
  "model": "", "promptVersion": 0,
  "system": "", "user": "",
  "rawResponse": "", "cleanedResponse": "",
  "criticVerdict": { "ok": false, "reason": "", "retryHint": "" },
  "tokens": 0, "durationMs": 0, "finishReason": ""
}
```

Для QA вместо `criticVerdict` пишется результат проверки (валидность JSON шага 1, проверка маркеров шага 3) и текст вопроса.

**Воспроизведение** (тест-хелпер `LlmTraceReplay`, UI не делаем):
- **Offline:** берёт `rawResponse` из файла и заново прогоняет очистку, разбор и Critic без сети. Так проверяем правки Critic и разбора.
- **Live:** отправляет сохранённые `system` и `user` в выбранную модель и показывает новый ответ и вердикт. Так проверяем правки промпта.

Detector и Parser отдельной трассы не имеют: воспроизводятся из `snapshots` в БД (`raw_text`, `clean_text`, `content_hash`).

Трассы содержат тексты материалов, лежат только локально, чистятся при старте приложения (старше `RetainDays`).

### 3.3. Как гоняем

- Прогон против реальных моделей это категория тестов `Live` (NUnit `[Category("Live")]`). Обычный прогон её исключает: `dotnet test --filter "Category!=Live"`. Иначе тесты жгут лимиты бесплатных моделей.
- Запускаем `Live` вручную после правки промпта, смены модели в цепочке или правки схемы. Версия промпта пишется в результат.
- Что делать при провале: смотрим трассу (раздел 2), правим промпт и поднимаем `version`.

## 6. Метрики

Отдельного модуля нет: метрики это запросы по `runs` и трассам (SQL лежит в `/docs/metrics.sql`).

| Метрика | Откуда |
|---|---|
| Доля Run по статусам | `runs.status` |
| Токены на Run | `runs.tokens_used` |
| Доля Run со свапом модели | `runs.stats.llmFallback` |
| Среднее число попыток Analyzer на Change | `sum(analyzerCalls) / sum(new + updated)` |
| Доля отказов Critic по номеру проверки | трассы (`criticVerdict.reason`) |

`analyzerCalls` = число попыток Analyzer за Run, включая повторы после отказа Critic; сетевые повторы и свап не считаются. Оценка среднего приблизительная: Pending, добранные из прошлых запусков, в `new + updated` не входят.

```sql
SELECT status, count(*) FROM runs WHERE topic_id = @topicId GROUP BY status;

SELECT sum((stats->>'analyzerCalls')::int)::float
     / NULLIF(sum((stats->>'new')::int + (stats->>'updated')::int), 0) AS attempts_per_change
FROM runs WHERE topic_id = @topicId AND status = 'Succeeded';
```
