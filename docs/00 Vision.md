# 00. Видение: цель и границы

## 1. Суть

Система по расписанию проверяет заданную предметную область, обнаруживает изменения по сравнению с прошлыми снимками, при изменениях обновляет описание предметной области и дописывает журнал изменений, а также отвечает на вопросы пользователя по этим изменениям.

### Документы системы

| Документ                    | Для кого     | Назначение                                                                                                    |
| --------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------- |
| Описание предметной области | пользователь | Актуальное целостное описание темы. Обновляется при изменениях                                                |
| Журнал изменений            | пользователь | Запись на каждое изменение, записи группируются по обновлению описания: что изменилось, где (источник), когда |
| Версии документа            | система      | Прежние версии описания. Нужны, чтобы не терять сведения и сравнивать «до/после»                              |

Версии хранятся неизменяемыми файлами, в БД лежат пути (D-002, D-019).

## 2. Пользователь и взаимодействие

### Платформа

Десктопное приложение на Avalonia. UI делается тонким слоем: вся логика (сбор, сравнение, агент, БД) живёт в отдельной библиотеке без знания об интерфейсе. Это позволит позже сменить оболочку (например, на веб).

### Экраны и функции

- **Статус:** мониторинг идёт / простаивает без задачи. Кнопка «Запустить сейчас» (ручной запуск, `trigger = Manual`, недоступна, пока идёт запуск, 07).
- **Окно настройки** (по кнопке «Начать мониторинг»):
    - предметная область;
    - периодичность мониторинга;
    - источники: тип + URL или поисковый запрос (указывает пользователь)
- **Журнал для пользователя:** что система делает сейчас и что делала ранее.
- **Чат** на главном экране: вопросы по изменениям. Каждый вопрос независим, подсказка в интерфейсе (08, раздел 5). Кнопка «Что изменилось с прошлого запуска».
- **Список документов** на главном экране: по клику открывается документ (описание, журнал изменений).

### Поведение системы

- **Один экземпляр:** повторный запуск приложения не создаёт вторую копию с отдельным мониторингом.
- **Пропущенные запуски:** если компьютер был выключен, при старте приложение проверяет, был ли вовремя выполнен мониторинг, и если нет, запускает его.
- **Расписание** хранится в БД (D-008) (вместе с историей запусков).
- **Работа в фоне:** один процесс, закрытие окна сворачивает приложение в трей.

## 3. Входит в MVP

- Десктопное приложение (Avalonia)
- Один агент, проводящий мониторинг
- Обнаружение изменений кодом (хэш/diff); LLM подключается только при наличии изменений
- Описание предметной области, журнал изменений, версии документа
- Работающий чат: на вопрос про последний запуск отвечает со ссылкой на запись журнала
- Работа в фоне (трей)
- Автозапуск приложения с ОС (только Windows)
- Один экземпляр приложения и догоняющий запуск при старте
- Консоль разработчика (Cli) для отладки и демонстрации, не заменяет UI

**Порядок реализации:** фон, автозапуск и трей делаются последним этапом MVP, они не влияют на архитектуру.

## 4. Не входит в MVP

- Многоагентность и адаптивная оркестрация (на диплом; интерфейсы шагов проектируются так, чтобы переход не требовал переделки)
- Несколько предметных областей одновременно
- Уведомления на почту и в мессенджеры
- Автоматический поиск источников (только источники, указанные пользователем)
- Кроссплатформенность (автозапуск и фон только под Windows, хотя UI на Avalonia)

## 5. Критерий готовности

Система считается рабочей, если:

- [ ] Первый запуск по теме создаёт описание минимум из 5 материалов
- [ ] Повторный запуск на тех же данных ничего не меняет и пишет «изменений нет»
- [ ] На тестовых изменённых данных создаётся запись в журнале
- [ ] После обновления прежняя версия документа сохранена, в новой версии не потеряны прежние сведения
- [ ] Каждое утверждение в документе имеет ссылку на источник
- [ ] Чат отвечает на «что изменилось» со ссылкой на источник и датой
- [ ] Чат при отсутствии данных так и говорит, а не выдумывает
- [ ] Повторный запуск приложения не создаёт второй экземпляр
- [ ] После перезапуска приложения расписание и данные сохраняются
- [ ] Пропущенный запуск выполняется при старте приложения

## 6. Сквозной сценарий

**Тема:** «гибридные интеллектуальные системы» **Источники** (сайты/ленты, до 5): habr.com, arXiv и т.д. **Периодичность:** раз в неделю **Материал** это отдельная статья или страница. Не более 10 новых материалов на запуск (на тему), см. 05.

### Запуск 1: первый

1. Открывается общий интерфейс, пользователь жмёт «Начать мониторинг».
2. В окне вводит тему, периодичность, источники.
3. Агент собирает материалы и создаёт первую версию описания.
4. Создаётся первая запись журнала.

### Запуск 2: через неделю, есть изменения

1. Система сама, без пользователя, запускает мониторинг.
2. Собирает данные и **сравнивает** с прежними снимками (хэш).
3. Для изменившегося проводит проверку информации (см. правило ниже).
4. Обновляет или дописывает описание с новыми сведениями, сохраняет прежнюю версию.
5. Пишет запись журнала: что добавлено или изменено, источник, дата.

### Запуск 3: изменений нет

1. Система запускает мониторинг и собирает данные.
2. Сравнивает с прежними снимками.
3. Изменений нет, работа прекращается без вызова LLM, в лог пишется «проверено, изменений нет».

### Вопрос пользователя

- **Вопрос:** «Что с последнего раза поменялось в гибридных интеллектуальных системах?»
- **Ответ ИИ:** «С <дата> добавлена обработка …, изменено … Источник: <ссылка>, запись журнала от <дата>.»

### Правило проверки информации

Информация попадает в документ в любом случае (проверка не блокирует работу), но помечается:

- «подтверждено N источниками» или
- «один источник».

Проверка истинности «в мире» не входит в задачу. Достаточно, что утверждение подтверждается текстом источника.

## 7. Ограничения

- **Платформа:** Сократ не используется.
- **Железо:** слабый ноутбук, высокая производительность не нужна.
- **Модели:** для обзоров по шаблону хватит простых локальных LLM или бесплатных моделей OpenRouter.

## 8. Риски

| Риск                                                    | Вероятность                | Что делаем                                                                                                                                                 |
| ------------------------------------------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Галлюцинации модели                                     | 40%                        | Каждое утверждение привязано к источнику; код проверяет, что ссылка есть и цитата найдена в тексте источника. При частых сбоях: смена модели               |
| Нет изменений по предметной области                     | 70%                        | Подготовленные тестовые данные для демонстрации; выбор быстроразвивающейся области                                                                         |
| Лимиты бесплатных моделей                               | 75%                        | Подбор подходящей модели; переход на локальную; повтор и откладывание запуска. Автоматический свап по цепочке моделей (D-031)                              |
| Источник изменил вёрстку                                | 20%                        | Предпочитать RSS и API. При ошибке разбора HTML писать в лог и пропускать источник, не роняя запуск                                                        |
| Компьютер выключен в момент запуска                     | 60%                        | При старте приложения проверять, был ли запуск вовремя; если нет, запустить                                                                                |
| LLM при переписывании документа теряет прежние сведения | 70% -> снято по построению | Analyzer возвращает только операции add_section / append_to_section, старый текст код не трогает (D-027). Остаточный риск: дубли и противоречия, не потери |

## Решения для DECISIONS.md

- D-001: Сократ не используется, чистый C# / .NET
- D-003: UI на Avalonia, логика в отдельной библиотеке без ссылок на UI
- D-004: Фон: один процесс с треем, служба отложена
- D-002: Один живой документ + журнал изменений + версии
- D-008: Расписание хранится в БД
- D-005: Проверка информации мягкая (пометка, а не блокировка)
