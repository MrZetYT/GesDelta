# 12. План работ

## 1. Формат работы

- Учебный режим: этап делится на микро-задачи по 30-60 минут. Цикл: задача → подсказка (вопросы, ссылки на нужный раздел документов, но не готовый код) → автор пишет → разбор. Готовый код только по просьбе автора.
- Единица оценки: рабочая сессия = 3-4 часа. Календарные даты ниже рассчитаны на 5 сессий в неделю, старт 12.10.2026.
- Дедлайн записки 5.12.2026. Цель: MVP готов к 22.11, две недели на записку.
- Записка пишется параллельно: главы по проектированию (цель, модель данных, архитектура, обнаружение изменений, агенты) из документов 00-11 пишутся во время этапов 0-4, не ждут кода. Главы про реализацию и результаты пишутся по ходу этапов 5-8.
- Конец каждого этапа: прогон его сценария из 11, отметка критериев из 00, запись в Decisions, если что-то решили по ходу.

## 3. Что в каждом этапе

Задачи даны списком, порядок внутри этапа примерный. «Учим» это то, что автор должен понять руками.

### Этап 0. Бумажный прогон и каркас

- Бумажный прогон: тема «гибридные интеллектуальные системы», сценарий из 00 (три запуска и вопрос), по документам. Результат: `/docs/paper-run.md` со списком дыр. Закрывает пункт чек-листа «готов кодить» из Readme.
- Solution и 7 проектов по 02 плюс `Cli`, правила ссылок между ними.
- Архитектурный тест зависимостей (Core без ссылок, App и Cli не используют Storage и Agents).
- Конфиг, user-secrets, Serilog в файл (11, раздел 1), `AddMonitoring()` пустой.
- PostgreSQL 17 локально, `DbContext`, первая миграция, `Database.Migrate()` при старте Cli.
- Пустой `FakeLlmClient : ILlmClient`.
- Учим: слоистая архитектура и проверка зависимостей тестом, DI в Generic Host.
- Готово: `dotnet test` зелёный, `Cli` стартует и применяет миграции.

### Этап 1. Хранилище и сбор

- Сущности и EF-конфигурации по 04, миграция. Сырой SQL в миграции: частичный уникальный индекс `runs`, GIN, `claims_id_seq`.
- Реальные URL источников: 2 живых (Habr RSS, arXiv по запросу), запись в 05 (закрывает TODO). Записанные ответы в `/tests/Data/`.
- `ISourceFetcher`: Rss, Arxiv. Канонизация URL и `external_id` (тесты).
- Collector: повторы через Microsoft.Extensions.Http.Resilience, паузы на хост, `reason` отказов.
- Parser: нормализация по 06, `IContentExtractor`, SHA256, тесты нормализации.
- Временный минимальный писатель Material и Snapshot (заменится Detector на этапе 2).
- Html-источник и `IRobotsPolicy` (библиотека или свой разбор, выбираем в начале задачи, запись в 13). Последняя задача этапа, первая в списке отсечения.
- Каркас golden set: собрать реальные материалы для кейсов из 11, раздел 3.
- CLI: `setup` (тема и источники из JSON), `collect` (собрать и показать, что сохранено).
- Учим: HttpClient и Resilience, System.ServiceModel.Syndication, Atom через XDocument, EF-миграции с сырым SQL.
- Готово: данные из 2 источников в БД, тесты Collector на записанных ответах.

### Этап 2. Обнаружение изменений

- `Detector`: хэш, DiffPlex по абзацам, пороги из конфига, `ISignificanceJudge` (правила).
- Транзакция Snapshot + Change (Pending), бюджет `MaxNewMaterialsPerRun`, round-robin по источникам.
- Тест-кейсы из 06, раздел 7 как юнит-тесты.
- CLI: `detect` (вердикт по каждому материалу, итоговые счётчики).
- Учим: транзакции EF, DiffPlex, как писать тест на таблицу кейсов.
- Готово: повторный запуск на тех же данных даёт только `Unchanged`, на изменённых записанных данных создаёт Change.

### Этап 3. Analyzer, Critic, DescriptionWriter

- `ILlmClient`, `LlmRequest`, `LlmResult` (Core), `MeaiLlmClient` для одной модели (OpenRouter), очистка ответа (`<think>`, обёртка JSON).
- Промпт `analyzer.md` (версия, EmbeddedResource), схема из C# records.
- Analyzer: сборка входа, обрезка по `MaxTextChars`.
- Critic: проверки №1-13 (одна попытка, без возврата).
- DescriptionWriter: sequence для id Claim, замена маркеров, операции в памяти, файл `v0001.md`, финальная транзакция.
- Трассы LLM (11, раздел 2).
- CLI: `analyze` (один Change), `doc` (текущая версия описания).
- Учим: Microsoft.Extensions.AI, JSON Schema из records, как строить промпт, Markdig.
- Готово: из 3-5 материалов получается `v0001.md`, каждый абзац с маркером, на `FakeLlmClient` и один раз на реальной модели.

### Этап 4. Полный конвейер

- `RunContext`, `FixedRunPipeline`, очередь Change (Pending + новые).
- Петля Critic → Analyzer с `feedback`, 3 попытки, `analyzerCalls`.
- Статусы Change и Run (07, раздел 6), финальная транзакция целиком.
- `FallbackLlmClient`: повторы по 07, свап по цепочке, уведомление в журнал.
- События прогресса, `IMonitoringService`: `StartMonitoring`, `RunNow`, `GetStatus`.
- Сценарии A-F из 11 на `FakeLlmClient`.
- CLI: `run` (полный запуск, прогресс в консоль), `status`.
- Учим: паттерн декоратор, CancellationToken, как тестировать повторы.
- Готово: сценарии A, B, C, D, E, F зелёные. Первый настоящий запуск `run` на реальных источниках и модели.
- Контрольная точка рисков (раздел 5).

### Этап 5. Вопросы и ответы

- QA шаг 1 (разбор вопроса), валидация JSON.
- Шаг 2: запросы из 04 (параметризованные), построение `@tsQuery` и `@patterns`.
- Шаблоны WhatChanged / WhenFirst, фразы из ресурсов, шорткат без LLM.
- Explain: разбор разделов (Markdig), шаг 3, проверка маркеров, сноски.
- `IMonitoringService.Ask`, `GetChangesSinceLastRun`, `GetChangelog`.
- CLI: `ask "..."`, `changes`.
- Golden set QA (10 вопросов) в `Live`. Сценарий H.
- Учим: полнотекстовый поиск Postgres, `websearch_to_tsquery`, SQL с `COUNT() OVER()`.
- Готово: «что изменилось» отвечает ссылкой и датой, «нет данных» отвечает фразой без вызова LLM.

### Этап 6. Расписание и автономность

- `IScheduler`: `BackgroundService` + `PeriodicTimer`, `TimeProvider` для тестов.
- Условие запуска, RetryDelay, серия «нечистых» Run, логирование решений (11, раздел 1).
- Закрытие Running как `interrupted` при старте, догоняющий запуск.
- CLI: `watch` (держит процесс, показывает решения планировщика).
- Учим: Hosted services, тест времени без `Thread.Sleep`.
- Готово: сценарий G зелёный, `watch` сам запускает Run по интервалу.

### Этап 7. Avalonia UI

- Перед стартом: строка в 13 про MVVM-библиотеку (CommunityToolkit.Mvvm или без неё, решение автора).
- Главное окно: статус, кнопка «Начать мониторинг» и «Запустить сейчас», журнал «что система делает сейчас» (событие прогресса).
- Окно настройки (тема, периодичность, источники).
- Чат со шорткатом «Что изменилось с прошлого запуска» и подсказкой.
- Список документов, показ описания, сноски `[c:id]` → `[1]` с карточкой, журнал изменений с группами и подгрузкой.
- Учим: Avalonia (отличия от WPF), привязки, ViewModel, UI-поток и события из фонового сервиса.
- Готово: весь сценарий из 00 проходится из окна без консоли.

### Этап 8. Фон и трей

- Трей (TrayIcon), крестик сворачивает, «Выход» отменяет запуск.
- Именованный Mutex, второй экземпляр завершается.
- Автозапуск Windows (HKCU Run).
- Догоняющий запуск при старте приложения.
- Ручная проверка: второй экземпляр, перезапуск, пропущенный запуск.
- Готово: все критерии из 00, раздел 5.

2. Explain в QA (остаются WhatChanged, WhenFirst, Unknown).
3. Автозапуск с Windows.
4. UI до минимума: статус, окно настройки, чат, список документов; журнал изменений показывается как документ.
