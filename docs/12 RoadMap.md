# 12. План работ

## 1. Формат работы

- Учебный режим: этап делится на микро-задачи по 30-60 минут. Цикл: задача → подсказка (вопросы, ссылки на нужный раздел документов, но не готовый код) → автор пишет → разбор. Готовый код только по просьбе автора.
- Единица оценки: рабочая сессия = 3-4 часа. Даты ниже пересчитаны 06.11.2026 из расчёта 4 сессии в неделю (D-061). Контрольная точка пересчёта: 22.11.
- Цель: сквозная демонстрация к 15.12.2026. Срок записки в этом файле был 5.12 (D-050). Если дедлайн остался прежним, демонстрация к нему не успевается, и дату нужно обсуждать отдельно.
- Записка пишется параллельно: главы по проектированию (цель, модель данных, архитектура, обнаружение изменений, агенты) из документов 00-11 пишутся во время этапов 1-4, не ждут кода. Главы про реализацию и результаты пишутся по ходу этапов 5-7.
- Конец каждого этапа: прогон его сценария из 11, отметка критериев из 00, запись в Decisions, если что-то решили по ходу.
- Объём урезан по D-061. Что отложено, какие швы заложены и как вернуть: 14_DEFERRED.

## 3. Что в каждом этапе

Задачи даны списком, порядок внутри этапа примерный. «Учим» это то, что автор должен понять руками.

### Этап 0. Бумажный прогон и каркас (готово)

- Бумажный прогон: `/docs/paper-run.md` со списком дыр.
- Solution и 7 проектов по 02 плюс `Cli`, правила ссылок. Архитектурный тест зависимостей.
- Конфиг, user-secrets, Serilog в файл, `AddMonitoring()` пустой.
- PostgreSQL 17 локально, `DbContext`, первая миграция, `Database.Migrate()` при старте Cli.
- `FakeLlmClient : ILlmClient` переносится на этап 3 (вместе с самим `ILlmClient`).
- Учим: слоистая архитектура и проверка зависимостей тестом, DI в Generic Host.
- Готово: `dotnet test` зелёный, `Cli` стартует и применяет миграции.

### Этап 1. Хранилище и сбор

- Сущности и EF-конфигурации по 04, миграция. Сырой SQL в миграции: частичный уникальный индекс `runs`, GIN, `claims_id_seq` (готово).
- Реальные URL источников записаны в 05: arXiv `neurosymbolic` и Habr RSS machine_learning. Для демо Habr идёт с `fullText = never` (D-062). Записанные ответы в `/tests/Data/`.
- Контракт `ISourceFetcher`, `FetchRequest`, `FetchedItem`, `FetchResult`, `FetchFailureReason` (готово).
- `RssSourceFetcher` (System.ServiceModel.Syndication), `ArxivSourceFetcher` (Atom через XDocument, `external_id` без версии, D-033). Тесты на записанных ответах.
- Канонизация URL и `external_id` (тесты).
- Collector: повторы через Microsoft.Extensions.Http.Resilience, паузы на хост из `HostDelaysMs` (приоритет над `ArxivDelayMs`, определить в коде или убрать `ArxivDelayMs`), `reason` отказов. Fetcher выбирается по `SourceType` (keyed DI).
- Parser: нормализация по 06 (включая хвост «Читать далее» у анонсов Habr), SHA256, ветка по `FromPage` для будущей докачки.
- Временный минимальный писатель Material и Snapshot (заменится Detector на этапе 2).
- Каркас golden set: собрать реальные материалы для кейсов из 11, раздел 3.
- CLI: `setup` (тема и источники из JSON, вызывает `StartMonitoring`), `collect` (собрать и показать, что сохранено).
- Отложено (14_DEFERRED, п. 1-2): Html-источник и `IRobotsPolicy`.
- Учим: HttpClient и Resilience, System.ServiceModel.Syndication, Atom через XDocument, EF-миграции с сырым SQL.
- Готово: данные из 2 источников в БД, тесты Collector на записанных ответах.

### Этап 2. Обнаружение изменений

- `Detector`: хэш, DiffPlex по абзацам, пороги из конфига, `ISignificanceJudge` (правила).
- База для diff: снимок последнего Change (D-056). Не откладывается.
- Транзакция Snapshot + Change (Pending), бюджет `MaxNewMaterialsPerRun`, round-robin по источникам, вердикт `OverBudget`.
- Тест-кейсы из 06, раздел 7 как юнит-тесты. Здесь подключаем NSubstitute и Testcontainers (13).
- CLI: `detect` (вердикт по каждому материалу, итоговые счётчики).
- Учим: транзакции EF, DiffPlex, как писать тест на таблицу кейсов.
- Готово: повторный запуск на тех же данных даёт только `Unchanged`, на изменённых записанных данных создаёт Change.

### Этап 3. Analyzer, Critic, DescriptionWriter

- `ILlmClient`, `LlmRequest`, `LlmResult` (Core), `MeaiLlmClient` для одной модели (OpenRouter), очистка ответа (`<think>`, обёртка JSON). Пустой `FakeLlmClient`.
- Конфиг `Chain` массивом, даже из одного элемента.
- Промпт `analyzer.md` (версия, EmbeddedResource), схема из C# records.
- Analyzer: сборка входа, обрезка по `MaxTextChars`.
- Critic: проверки №1-13 (одна попытка, без возврата).
- DescriptionWriter: sequence для id Claim, замена маркеров, операции в памяти, файл `v0001.md`, финальная транзакция.
- Трассы LLM (11, раздел 2). Не откладываются.
- CLI: `analyze` (один Change), `doc` (текущая версия описания).
- Учим: Microsoft.Extensions.AI, JSON Schema из records, как строить промпт, Markdig.
- Готово: из 3-5 материалов получается `v0001.md`, каждый абзац с маркером, на `FakeLlmClient` и один раз на реальной модели.
